# travel-plans 全面刷新 設計書

**作成日**: 2026-08-09
**対象リポジトリ**: `y-shinozaki/travel-plans`
**現状**: 単一 `index.html`（2,521行）。旅程カレンダーと Leaflet 地図のみ。GitHub Pages で公開中。

---

## 1. 目的

5 つの要求を満たすためにアプリを再構成する。

1. 別のデザイン仕様で見た目を刷新する
2. 二人分のチェックボックス付き持ち物リストを作る
3. 要所にコメントを残せるようにする
4. Gmail と LINE の情報を JSON に格納し、Pages から検索できるようにする
5. 検索画面へはパスワード入力で遷移する

検討の過程で、2 と 4 に付随して次が追加された。

6. 持ち物リストはユーザーが項目・区分を追加／修正／削除／並べ替えできる
7. カレンダーの予定も同様に追加／修正／削除できる
8. 編集結果を UI の操作だけで同行者に共有できる

### 3.4 カテゴリ色

Aman は無彩色のみのため、カレンダーの識別に必要な 5 色を派生させた。

**低彩度の濃色をベタ塗りで並べると混色して濁る**ため、面はティント、識別は縦バーと
アイコンに担わせる。各カテゴリは「アクセント / ティント地 / 文字」の 3 値を持つ。

| カテゴリ | アクセント | ティント地 | 文字 |
|---|---|---|---|
| 移動 | `#3F5C50` | `#D6E8DB` | `#22352D` |
| 観光 | `#7E5318` | `#F6E7C0` | `#4A3212` |
| 食事 | `#A54A2C` | `#F9E2D7` | `#58281A` |
| 宿泊 | `#2F566F` | `#D8E6F4` | `#1C3446` |
| 買物 | `#6A4C78` | `#EDE2F2` | `#38263F` |

検証値: 文字コントラスト 9.7〜11.1、ティント上のアクセント 4.67〜6.17、
ティント同士の最小色距離 21。

カテゴリクラスは CSS カスタムプロパティのみを供給し、面の塗り方は各コンポーネントが決める。
地図ピンや詳細バッジは小面積なのでアクセント色のベタ塗りを使う。

```css

.ev        { background: var(--bg); color: var(--tx); border-left: 3px solid var(--bar); }
```

### 3.5 アイコン

アイコンフォントは使わない。単一のインライン SVG スプライト（`<symbol>` 約 30 個）を
`icons.js` が各ページに注入し、`<use href="#i-xxx">` で参照する。

- 線幅 1.0〜1.4px。1px ヘアラインと太さを揃える
- `stroke: currentColor` で色を継承
- 追加ネットワークリクエストなし

### 3.6 モーション

| 対象 | 内容 |
|---|---|
| 見出し | 行マスクからせり上がる（1.05s） |
| セクション | フェード＋22px 上昇。並列要素は 0.08〜0.12s ずつ時差 |
| 主要画像 | `scale(1.1) → 1` のスローズーム（2.4〜2.6s） |
| ボタン | 地色が右へ抜ける＋アイコンが 5px 進む |
| チェックボックス | パスを `stroke-dashoffset` で 0.42s かけて描画 |
| カレンダー | イベントを 12ms 刻みで順に出現 |
| 一覧行 | ホバーで左に せり出し、画像が 1.08 倍＋彩度回復 |
| イージング | `cubic-bezier(.22, 1, .36, 1)` |

`prefers-reduced-motion: reduce` で全アニメーションを無効化する。

**スクロール連動の実装上の注意**: IntersectionObserver 単体では、アンカージャンプや
スクロール位置復元で要素をまたいだときに `is-in` が付かず、コンテンツが `opacity: 0` の
まま残る。`threshold: 0` に加えて、スクロール時に「ビューポート下端より上に来た未表示要素を
無条件で表示する」掃引処理を併用する。

また `reveal`（フェード）と `drawline`（罫線を引く）を同一要素に付けてはならない。
CSS の `animation` プロパティが後勝ちで上書きされ、要素が不可視のまま残る。

### 3.7 レスポンシブ

ブレークポイントは 1180px と 760px。

- 1180px 以下: 地図とサイドバー、詳細パネル、メニューカード、ログインが縦積み
- 760px 以下: セクション間隔を 96px に縮小、検索結果とタイプスケールを 1 カラム化
- カレンダーは 760px 以下で横スクロール。時間列は `position: sticky; left: 0` で固定

## 4. データモデル

すべて JSON。置き場所は 3 種類。

| データ | リモート（正） | ローカル | 書き換える主体 |
|---|---|---|---|
| 旅程 | `assets/data/events.json` | `localStorage["tp:events"]` | ユーザー（UI） |
| 持ち物 | `assets/data/packing.json` | `localStorage["tp:packing"]` | ユーザー（UI） |
| コメント | `assets/data/comments.json` | `localStorage["tp:comments"]` | ユーザー（UI） |
| Gmail / LINE | `assets/data/archive.enc` | なし（復号は毎回） | 変換スクリプト |

すべてのファイルはオブジェクトを最上位に置き、`updatedAt`（ISO8601）を持つ。
配列を最上位にしない。版の比較に必要なため。

### 4.1 旅程（events.json）

旅行日の配列 `days` も同じファイルに置く。`startDay` / `endDay` はこの配列の添字であり、
別ファイルに分けると添字がずれたときに壊れるため。

```jsonc
{
  "updatedAt": "2026-08-09T10:00:00+09:00",
  "days": [
    { "dow": "水", "date": "8/12" },
    { "dow": "木", "date": "8/13" }
    // ... 6 日分
  ],
  "events": [ /* 下記のイベント */ ]
}
```

イベント 1 件の形:

```jsonc
{
  "id": "ev-3",
  "cat": "cat-hotel",              // cat-move | cat-sight | cat-food | cat-hotel | cat-shop
  "title": "バンコクホテル",
  "allDay": false,
  "startDay": 0,                   // days[] のインデックス
  "endDay": 2,                     // startDay と異なれば日をまたぐ
  "start": 15.0,                   // 10進時間。allDay のときは持たない
  "end": 11.0,
  "location": "137 ピラーズ レジデンス バンコク",
  "lat": 13.7278,
  "lng": 100.5601,
  "url": "",
  "notes": "",
  "image": ""
}
```

- 旧形式の `d`（単日）と `multiDay` は廃止し、常に `startDay` / `endDay` を持つ
- 表示用の `time` 文字列（`"10:35 → 15:05"`）は**保持しない**。`start` / `end` から生成する。
  二重管理はずれるため
- `lat` と `lng` は両方揃ったときのみ地図にピンを立てる。片方だけなら座標なしとして扱う

日をまたぐイベントは `expandEvents()` が日ごとのセグメントに割って描画する。
実体は 1 件なので、削除すると全セグメントが消える。

```
startDay: start 〜 24 / 中間日: 0 〜 24 / endDay: 0 〜 end
```

### 4.2 持ち物リスト（packing.json）

```jsonc
{
  "updatedAt": "2026-08-09T10:00:00+09:00",
  "members": { "a": "Yuichi", "b": "Partner" },
  "groups": [
    {
      "id": "g-valuables",
      "name": "貴重品・書類",
      "icon": "i-key",
      "items": [
        { "id": "passport", "name": "パスポート", "note": "残存6か月以上",
          "a": true, "b": true }
      ]
    }
  ]
}
```

`a` / `b` は二人分のチェック状態。区分・項目とも追加／改名／削除／並べ替えができ、
項目は区分をまたいで移動できる。

### 4.3 コメント（comments.json）

対象キーと本文だけを持つ単純な構造。1 つのモジュールで 4 か所の要件を満たす。

```jsonc
{
  "updatedAt": "2026-08-09T10:00:00+09:00",
  "byTarget": {
    "event:ev-3":      [{ "id": "c1", "who": "Yuichi",
                          "at": "2026-08-04T07:55:00+09:00",
                          "text": "渡し船は 5B。" }],
    "day:1":           [],
    "packing:adapter": [],
    "global":          []
  }
}
```

コメントも公開対象とする。「この店は予約済み」のような内容は同行者と共有する価値が
あるため。個人メモに留めたい要求が出た場合は、公開しない `private` 種別を足す。

### 4.4 検索アーカイブ

```jsonc
{
  "updatedAt": "2026-08-09T10:00:00+09:00",
  "records": [
    {
      "id": "gm-001",
      "source": "gmail",              // gmail | line
      "title": "【予約確定】137 Pillars Residences Bangkok",
      "body": "...全文...",
      "from": "booking@137pillars.com",
      "at": "2026-06-21T09:14:00+09:00",
      "refs": ["HTL-4471-2026"]       // 予約番号など、抽出できた識別子
    }
  ]
}
```

## 5. 保存と共有

### 5.1 方針

- リモートの JSON が**正**
- 編集は即座に localStorage へ入る（下書き）
- 「公開」を押すと GitHub Contents API 経由でリモートへコミットされる
- 同行者はページを開くだけで最新を受け取る

トークンを持つ端末（Yuichi）だけが公開でき、持たない端末は閲覧と下書き編集のみ。
役割が自然に分かれる。

### 5.2 読み込み時の流れ

各 JSON はトップレベルに `updatedAt` を持つ。localStorage には取り込んだ時点の
`baseUpdatedAt` を併せて保存する。

```
リモートを fetch
  ├ ローカルなし                       → リモートを取り込む
  ├ remote.updatedAt == baseUpdatedAt  → ローカルを使う
  ├ remote が新しく、ローカルに未公開の変更なし → 静かにリモートへ更新
  └ remote が新しく、ローカルに未公開の変更あり
        → 画面上部にバーを出す
          「新しい版があります ／ 取り込む ・ 自分の変更を残す」
```

**リモートで黙って上書きしない。** 同行者が手元で付けたチェックを失わせないため、
取り込みは必ず明示操作にする。

fetch が失敗した場合（オフライン、Pages 障害）はローカルのデータで動作を継続し、
「最新の確認ができませんでした」とだけ表示する。機能は落とさない。

### 5.3 公開の流れ

GitHub Contents API を使う。

```
1. GET  /repos/{owner}/{repo}/contents/assets/data/events.json  → 現在の sha
2. updatedAt を現在時刻に更新
3. PUT  同 URL  { message, content: base64(JSON), sha }
4. 成功 → baseUpdatedAt を更新、「公開しました」を表示
```

注意点:

- **base64 化に `btoa()` を直接使わない**。日本語を含む UTF-8 は例外になる。
  `TextEncoder` でバイト列にしてから base64 化する
- sha が古い場合 API は 409 を返す。別端末から公開した場合に起きる。
  「リモートが更新されています。取り込んでから公開し直してください」と表示し、
  勝手に上書きしない
- Pages への反映には 1 分程度かかる。公開直後に「反映まで少し時間がかかります」と添える
- 公開は 3 つの JSON をまとめてではなく、変更のあったファイルのみ

### 5.4 トークンの扱い

- **fine-grained personal access token** を使う
- 権限は本リポジトリの **Contents: Read and write のみ**。他のリポジトリ・他の権限は与えない
- 有効期限を設定する（旅行終了後まで）
- コードにもリポジトリにも書かない。UI から一度入力し、`localStorage["tp:gh-token"]` に保存
- 「トークンを削除」操作を設定画面に置く
- トークン未設定の端末では「公開」ボタン自体を出さない

## 6. 認証と暗号化

### 6.1 合言葉の二重の役割

1. `index.html` からの遷移を制限する目隠し
2. 検索データを復号する鍵

GitHub Pages は誰でも URL を開けるため、JS のパスワード判定はコードを読めば素通りできる。
旅程・持ち物は平文のままなので、この判定は**目隠し以上のものではない**と割り切る。
検索データだけは本物の暗号で保護する。

### 6.2 暗号仕様

| 項目 | 内容 |
|---|---|
| 鍵導出 | PBKDF2-HMAC-SHA256、反復 600,000 回、ソルト 16 バイト（乱数） |
| 暗号 | AES-GCM 256bit、IV 12 バイト（乱数） |
| ファイル構造 | `"TPENC1"`(6) + salt(16) + iv(12) + ciphertext |

合言葉が違えば GCM の認証タグ検証が失敗する。復号例外を捕まえて
「合言葉が違います」と表示する。復号は WebCrypto でブラウザ上のみ。

### 6.3 セッション

認証成功時、導出した鍵を `sessionStorage` に保持し、ページ遷移のたびの再入力を避ける。
タブを閉じるとリセットされる。各ページの先頭でフラグを確認し、未認証なら
`index.html` へリダイレクトする。

### 6.4 CDN 依存の排除

**書き込み権限を持つトークンをブラウザに置く以上、外部 CDN の JS を無条件に読み込むのは
危険。** unpkg 上の Leaflet が改竄された場合、トークンを外部へ送ることも、
リポジトリへ任意の内容を push することもできる。

対策として **Leaflet を `assets/vendor/leaflet/` に自前で配置する**。
Google Fonts は CSS とフォントのみでスクリプトを実行しないため継続利用してよいが、
可能なら同様にセルフホストする。

## 7. 各ページの仕様

### 7.1 index.html

- 左に写真（スローズーム）、右に合言葉入力の 2 カラム。1180px 以下で縦積み
- 認証成功でメニューへ遷移。旅程／データ検索／持ち物リストの 3 カード
- 各カードは写真＋番号＋説明。ホバーで写真が 1.06 倍、彩度が戻る

### 7.2 schedule.html

**カレンダー**
- 横軸 6 日、縦軸 1 時間 44px（`HOUR_H`）。表示時間帯は選択式（既定 6:00–22:00）
- 終日イベントは専用の行
- 同時刻のイベントはレーン分割で横に並べる
- カテゴリでの絞り込み

**予定エディタ**
- 通常時にイベントをクリック → 右からシートが出て詳細表示、「この予定を編集」でフォームへ
- 「予定を編集」ON でクリックすると直接フォーム。イベントに破線の枠が出る
- 「予定を追加」で空のフォーム
- 削除はフォーム下部で 2 度押し
- 閉じるのは ✕ / 背景クリック / Esc

**入力検証**（すべてインライン表示。`alert` / `confirm` は使わない）

| 条件 | メッセージ |
|---|---|
| タイトルが空 | タイトルを入力してください。 |
| 終了日 < 開始日 | 終了日が開始日より前になっています。 |
| 同日内で 終了時刻 ≤ 開始時刻 | 同じ日の中では、終了時刻を開始時刻より後にしてください。 |
| 緯度が −90〜90 の外 | 緯度は −90〜90 の数値で入力してください。 |
| 経度が −180〜180 の外 | 経度は −180〜180 の数値で入力してください。 |

日をまたぐ場合は `15:00 → 11:00` が正しいため、時刻の前後関係は検査しない。

**地図**
- 座標を持つイベントにピン。同一座標は重複排除
- ピンは円形、アクセント色、白フチ
- 一覧の行をクリックで `flyTo` とポップアップ

### 7.3 packing.html

- 二人分の進捗（達成数と細いバー）
- 表は「区分 → 項目」の 2 階層
- 通常時は読むだけの静かな見た目。「リストを編集」で編集モードへ

**編集モードでできること**

| 操作 | 手段 |
|---|---|
| 項目の追加 | 区分ごとの「項目を追加」。追加後は入力欄にフォーカス |
| 区分の追加 | 表の最下部 |
| 名称・メモの編集 | 行がそのまま入力欄になる |
| 並べ替え | ドラッグハンドル、または ↑↓ ボタン |
| 区分をまたぐ移動 | ドラッグ、または ↑↓ で端に達したとき隣の区分へ送る |
| 削除 | ✕ を 2 度押し。区分は「4件ごと削除」と中身の数を出す |

**ドラッグは Pointer Events で実装する。** HTML5 Drag & Drop はタッチ端末で動作しない。
ハンドルに `touch-action: none` を付け、スクロールとの競合を避ける。
`pointermove` / `pointerup` は**ハンドルではなく `window`** に登録する。
`setPointerCapture` が失敗する環境で、ポインタがハンドルから外れた瞬間に
ドラッグが止まるため。capture は補助として `try/catch` で囲む。

並び順は DOM を正として、指を離した時点で `data-id` を読んで配列を再構築する。
ドラッグ中に再描画しないので動きが途切れない。

ドラッグが使えない環境のために ↑↓ ボタンを常に併設する。

### 7.4 archive.html

- 合言葉で復号してから検索欄を表示
- 全文の部分一致。ソース（Gmail / LINE）と「予約番号あり」で絞り込み
- 結果は一致箇所をハイライト。クリックで全文表示
- 件数を明示する

### 7.5 コメント

`event:<id>` / `day:<n>` / `packing:<id>` / `global` の 4 種類の対象キーを
1 つのモジュールで扱う。設置場所は予定シート、日付ヘッダー、持ち物の各行、
旅程ページ下部のフリーメモ欄。

## 8. 変換スクリプト

`tools/build-archive.mjs`（Node、依存なし）

```
private/gmail.json   Gmail から抽出した生データ
private/line-*.txt   LINE の「トーク履歴を送信」で出力したテキスト
        ↓
    正規化（共通スキーマへ、日時を ISO8601 に、予約番号らしき文字列を抽出）
        ↓
    合言葉で暗号化
        ↓
assets/data/archive.enc
```

- 合言葉は環境変数から受け取る。引数に書かない（シェル履歴に残るため）
- `private/` は `.gitignore` 済みであることをスクリプト冒頭で確認し、
  含まれていなければ中断する
- LINE のエクスポートはタブ区切りで、日付行とメッセージ行が混在する形式。
  日付行を状態として保持しながら走査する
- Gmail の抽出は MCP 経由で行い、結果を `private/gmail.json` に保存する（手作業）

## 9. エラー処理の方針

- **ブラウザの `alert` / `confirm` / `prompt` を使わない。** ページ全体をブロックするため。
  破壊的操作は「2 度押し」で確定させ、エラーはインラインに表示する
- 失敗を握りつぶさない。fetch 失敗、復号失敗、公開の 409、JSON の不正はすべて
  画面に理由を出す
- リモート取得に失敗しても、ローカルデータでの動作は継続する

## 10. 検証方針

ビルドもテストランナーも持たないプロジェクトなので、ブラウザ上で数値を測って確認する。
各フェーズの完了時に以下を確認する。

**レイアウト**
- 390px と 1440px で `document.scrollWidth <= innerWidth`（横溢れなし）
- カレンダーのイベントが列の矩形からはみ出していない
- `.reveal:not(.is-in)` が 0 件（最下部まで一気にジャンプした後も）

**色**
- カテゴリごとに 文字とティント地のコントラスト比 7.0 以上
- ティント同士の色距離 20 以上

**機能**
- 予定: 追加／編集／削除／終日への変換／日またぎ（セグメント数と高さ）／全バリデーション
- 持ち物: ボタン移動／区分またぎ移動／区分並べ替え／ドラッグ 3 種／空区分へのドロップ／
  2 度押し削除。全操作を通じて項目総数が保たれること
- 公開: sha 競合時に上書きしないこと、UTF-8 の base64 化が壊れないこと
- 復号: 誤った合言葉でエラーメッセージが出ること

**アイコン**
- `svg.ico` の描画サイズが全て非ゼロ、未解決の `<use>` が 0 件

## 11. 決定事項

| 論点 | 決定 | 理由 |
|---|---|---|
| Gmail / LINE の保護 | JSON を AES-GCM で暗号化して配置 | 公開 Pages でも中身が読めない。合言葉が復号キーを兼ねる |
| 旅程・持ち物の保護 | 平文のまま | 暗号化すると編集のたびにビルドが要る。目隠しの認証で足りる |
| 保存先 | localStorage を下書き、リポジトリの JSON を正 | 外部サービスを増やさずに共有を成立させる |
| 共有手段 | UI から GitHub Contents API で直接公開 | ターミナルもファイル受け渡しも不要。編集者は一人 |
| 同期の方向 | 明示操作で取り込む | 同行者の手元の変更を黙って消さない |
| デザイン参照元 | aman.com | 旅行という題材に合い、写真が映える |
| 角丸 | 5 段階のトークンを導入 | Aman の 0px は硬いという判断 |
| ページ構成 | ページ別 HTML ＋ 共通 CSS / JS | 単一ファイルの肥大化を避ける |
| ドラッグ実装 | Pointer Events | HTML5 DnD はタッチで動かない |
| Leaflet | セルフホスト | 書き込み権限のトークンを置くため、CDN 改竄の影響を受けない |

### 採用しなかった案

- **Firebase / Supabase での同期**: アカウント作成、API キー管理、セキュリティルール設定が
  必要になる。編集者が一人なら GitHub への直接公開で足りる
- **全データの暗号化**: 旅程を 1 行直すたびにビルドスクリプトの実行が必要になる
- **1 ファイルのままタブ切り替え**: 4,000〜5,000 行に肥大化する
- **アイコンフォント**: 追加リクエストと FOUT が発生する。インライン SVG で足りる
- **`time` 文字列の保持**: `start` / `end` との二重管理でずれる

## 13. Phase A からの繰り越し

Phase A の実装とレビューで見つかり、Phase A の範囲外として意図的に残した項目。
着手前にこの節を読むこと。

### セキュリティ（Phase B の公開機能に直結する）

- **`ev.url` のスキーム検証がない。** `renderEventDetail` は `<a href>` に
  `escapeHtml` は掛けるが、`javascript:` スキームは素通りする。現状は `events.json` が
  リポジトリ管理下なので到達しないが、**Phase B で url が編集可能になった時点で
  実際の穴になる。** 同じページに書き込み権限のトークンが載る点に注意
- **CSP を入れていない。** `<meta http-equiv="Content-Security-Policy">` で
  `script-src` から `unsafe-inline` を外せば、文字列組み立てによる注入をまとめて塞げる。
  今なら `packing.html` / `archive.html` のインライン module を外部ファイルへ移すだけで済む。
  トークンの導線ができたあとに入れると監査コストが上がる
- **画像を 4 つの外部ホストから直リンクしている**（`menu.js` と `events.json`）。
  リンク切れと閲覧者 IP の漏出。`.gitignore` の `*.png` / `*.jpg` を
  スクリーンショット用のパスに絞れば自前配置できる

### 設計の負債

- **`map.js` の再描画判定が `id` と座標だけを見ている。** `title` や `image` を
  その場で編集しても一覧が更新されない。Phase B の編集機能で顕在化する
- **`schedule.js` の `catch` が描画時の例外もデータ読込失敗として表示する。**
  実際の原因は `console.error` には出る
- **`dayRangeLabel` は `endDay` 未定義で落ちる。** `expandEvents` は `??` で
  フォールバックしており不整合。正しい直し方は読み込み時に一度正規化すること。
  2 つ目の `??` を足して糊塗しないこと
- **`iconOf` は `ev.icon` があると `ev.cat` を検証しない。** 不正なカテゴリが
  カレンダーだけ無言で通る（地図と詳細シートは throw する）
- **`hhmmToDec` は `"24:30"` を受け入れる。** Phase B でフォーム入力を通す前に上限を決める
- **シートに閉じる操作を拒否する手段がない。** Phase B の編集フォームは未保存の変更を
  黙って捨てることになる。`confirm()` は使えないので `canClose` 述語などが要る
- **`sheet.open()` は本文を文字列で受け取る。** フォームを載せるなら Node も
  受け取れるほうが、描画後に `bodyEl` から入力欄を引き直さずに済む

### 小さいもの

- CSS の色リテラル検査（`tokens.test.js`）は対象ファイルをハードコードしている。
  `packing.css` を足すと無検査になる
- 名前付き色（`red` など）とコメント内の色は検査対象外
- `days.length === 0` で `repeat(0, 1fr)` という不正な CSS になる
- `.ev` の padding が `box-sizing: border-box` 下で高さの下限になり、表示終端まで
  13.6 分未満のイベントで約 5.6px はみ出す（実データでは発生しない）
- メニューカードが `ul` / `li` で包まれていない
- Phase B/C 用の CSS 約 250 行が今も配信されている（モックからの一括転記による）
- `createMap()` と `createSheet()` の本体は `node --test` の対象外。ブラウザ実測でのみ検証
