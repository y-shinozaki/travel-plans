## B2 に入る前に知っておくこと

### `createPublishUI()` も旅程専用（2026-08-10 に発見。設計書 §13 に未記載）

`createSync()` が旅程専用だった問題（設計書 §13 の先頭項目）は B4 で解消し、
`draftKey` / `baseKey` / `validate` / `commitMessage` / `codec` の 5 つを注入できる。
**しかし `publish-ui.js` に同じ形の依存が 2 つ残っている:**

1. `validateEvents` を module top で import し（`assets/js/publish-ui.js:27`）、
   `doPublish()` が直に呼ぶ（`:411`）。持ち物ページで使い回すと、
   持ち物データが `validateEvents` に落ちて**公開ボタンが必ず失敗する**
2. `MESSAGES` の文言に「旅程」が埋め込まれている（`offline` / `remoteIsNewer` ほか）

**5 つの注入口と同じ危険がここにもある。** 片方だけ直さないこと。

### `sync.js` の 5 つは必ず揃えて渡す

一部だけ差し替えると、その JSON が自分の検証を通ったうえで
`store.write(draftKey, …)` が旅程の既定キーへ書き、**旅程の未公開の編集がその瞬間に消える**
（設計書 §13）。B4 の繰り越し Minor に
「**注入した `draftKey` で `saveLocal()` を回すテストが無い**」があり、
設計書が名指しする失敗を守るアサーションが現状どこにも無い。
**B2 の最初のタスクはこのテストにする。**

## iPhone から作業を続ける（Remote Control）

**このセッションを iPhone の Claude アプリから操作する。** クラウド側の別セッションではなく、
手元のセッションをそのまま遠隔で見て・指示する。

```bash
# 現在のセッションを引き継いで Remote Control を有効にする
claude --remote-control -c

# 引き継がずに新しく始める場合（このファイルを読ませるところから）
claude --remote-control
```

`~/.claude/settings.json` は `agentPushNotifEnabled` / `inputNeededNotifEnabled` が
どちらも `true` なので、**判断が要る場面では iPhone に通知が届く。**

### この経路でできないこと

- **合言葉とトークンの入力**（安全上の規約で私は入力できない）。
  鍵やトークンの設定が要る場面は、その 2 手だけ本人が行う
- **旅程の内容の変更**。`events.json` は暗号文で、変更は画面からしかできない
  （`travel-plans-publish-flow` のメモ参照）。iPhone から直すなら Safari で
  GitHub Pages を開いて編集画面を使う経路になる
- **「公開」は取り消せない。** 押す前に必ず日別の一覧を見せて承認を取ること
