## 持ち物リストページ: 合言葉を持つ人が確認すること

自動テスト（`node --test`）はデータの形と描画の配線までしか確認できない。
実際にブラウザで合言葉を入れて開く手順は、合言葉を持つ人（私は入力できない）にしか
確認できない。以下を実機（できればスマートフォンを含む）で、`python3 -m http.server 8000`
を起動した状態か、公開先 `https://y-shinozaki.github.io/travel-plans/` から順番どおりに
試してほしい。

**途中で「書かれているとおりにならない」場合は、その場で止めてください。** 次の手順には
進まず、どの番号で・何が・期待とどう違ったか（できればスクリーンショットとブラウザの
コンソールのエラー）を教えてください。とくに手順 12（旅程が無事かの確認）は、
他のどの手順の失敗より優先して報告してください。

**「最新の持ち物リストを確認できませんでした」という薄い青のバーが出たら、
それは通信に失敗しただけです。** 電波の弱い場所ではふつうに起こります。
表示中のリストは手元の下書きなので消えていません。これ単体では止めず・報告不要です。

1. **合言葉を入れて開く。** トップページの合言葉欄に入れて「開く」を押し、
   旅程ページが問題なく開くことを確認する（既存の合言葉が壊れていないこと）。
2. **「持ち物」へ移動した直後、リストが読み込まれるより前の段階で、ツールバーに
   トークンまわりのボタンが出ていることを確認する。**（トークン未設定なら
   「公開用トークンを設定」、設定済みなら「トークン設定」に加えて「公開」ボタン。）
   ここが抜けている（何もボタンが無い）場合は、リモートが壊れたときに画面から直す
   手段が無いことを意味するので、必ず報告してください。
3. **公開済みの持ち物リストが表示される。** 2026-08-10 に最初の公開が済んでいるので、
   区分ごとに項目が並び、上部に進捗のバーが出ることを確認する
   （真っ白な画面やエラーが出た場合は、そこで止めて報告してください）。
4. **「リストを編集」を押す。** ボタンの表示が「編集を終える」に変わり、
   「区分を追加」ボタンが現れることを確認する。
5. **「区分を追加」→「項目を追加」→ 名前とメモを入力する。** 新しい区分（「新しい区分」）
   が追加され、その中に「項目を追加」で項目（「新しい項目」）が増えることを確認する。
   項目名の入力欄に文字を入れたあと **Tab キーでメモの欄へ移動できる**こと（フォーカスが
   `<body>` へ落ちて何も反応しなくならないこと）を確認する。保存されて表示が更新される
   ことも確認する。
6. **チェックを付ける。** 追加した項目の 2 人分のチェックボックスを押し、
   **進捗のバーと数字（達成数・パーセント）が動く**ことを確認する。
7. **キーボードだけで ↑↓ を連打する。** マウス・タッチを使わず、Tab で項目の ↑ ボタンへ
   到達して Enter（またはスペース）で押す。**押したあとも同じボタン（または隣接する
   ボタン）にフォーカスが残っている**こと（`<body>` に落ちて、次に動かすのに文書の先頭から
   Tab をやり直す羽目にならないこと）を確認する。同じ区分内で上下に動くこと、
   **区分の端まで来たら隣の区分へ送られる**ことも合わせて確認する（区分自体の ↑↓ ボタンも
   同様）。**この手順は B5 で持ち越している確認事項です** ── B5 の前半でフォーカスキーの
   組み立て方を `assets/js/focus-key.js` へ抽出し、`packing.js` の呼び出し方が変わったため、
   抽出後の挙動をまだ人が実機で確かめていません。他の手順以上に注意して見てください。
8. **ドラッグハンドルで並べ替える。** **スマートフォンの実機で**ドラッグハンドル
   （項目行の左端のつまみ）を指で掴んで並べ替える。ページ全体がスクロールしてしまう
   ことがないか確認する。
9. **削除ボタンを 1 度押して身構え、2 度目で消えること**を、項目・区分の両方で確認する
   （1 度目は「もう一度で削除」に表示が変わるだけで、まだ消えないこと）。
10. **タブを閉じて開き直す。** 「持ち物」ページを再度開き、**下書き（さきほどの編集内容）
    が残っている**ことを確認する。
11. **公開する（トークンを持つ端末のみ）。** トークンを設定していれば「公開」ボタンを
    押し、公開が成功すること、コミットへのリンクが表示されることを確認する。
    公開後、別の端末（または別のブラウザ）で「持ち物」ページを開き直し、公開した
    内容が反映されていることを確認する。
12. **最重要: 旅程ページを開いて旅程が無事であることを確認する。**
    「持ち物」でどれだけ編集・公開しても、ナビの「旅程」を押して旅程ページに戻り、
    **カレンダー・地図・イベントの内容がそれまでと変わっていない**ことを確認する。
    ここで旅程が消えている・壊れている場合は重大な不具合なので、
    他のどの手順の失敗よりも優先して直ちに報告してください。

## iPhone から作業を続ける（Remote Control）

**このセッションを iPhone の Claude アプリから操作する。** クラウド側の別セッションではなく、
手元のセッションをそのまま遠隔で見て・指示する。

```bash
# 現在のセッションを引き継いで Remote Control を有効にする
claude --remote-control -c

# 引き継がずに新しく始める場合（このファイルを読ませるところから）
claude --remote-control
```

`~/.claude/settings.json` は `agentPushNotifEnabled` / `inputNeededNotifEnabled` が
どちらも `true` なので、**判断が要る場面では iPhone に通知が届く。**

### この経路でできないこと

- **合言葉とトークンの入力**（安全上の規約で私は入力できない）。
  鍵やトークンの設定が要る場面は、その 2 手だけ本人が行う
- **旅程の内容の変更**。`events.json` は暗号文で、変更は画面からしかできない
  （`travel-plans-publish-flow` のメモ参照）。iPhone から直すなら Safari で
  GitHub Pages を開いて編集画面を使う経路になる
- **「公開」は取り消せない。** 押す前に必ず日別の一覧を見せて承認を取ること
